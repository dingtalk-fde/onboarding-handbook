# FDE 客户交付流程（从商机到上线）

> 文档负责人：FDE 交付部总监 韩东 & SA 团队负责人 方哲｜最近更新：2026-10-01

## 全流程概览

| 阶段 | 周期 | 主导 | 关键产出 | 出口标准（Gate） |
|------|------|------|----------|-----------------|
| 0. 商机评估 | 1 周 | 销售 + SA | 商机评估表 | 方哲 + 韩东同意投入 |
| 1. Discovery 诊断 | 1–2 周 | SA + FDE | Discovery 报告：流程地图、数据清单、指标基线、风险 | 客户确认痛点与目标指标 |
| 2. PoC | 2–4 周 | FDE | 可运行 Agent、**PoC 评测集**、评测报告 | 达到双方约定的验收指标 |
| 3. 签约 | 1–3 周 | 销售 + SA + 法务 | SOW、DPA（数据处理协议） | 合同与 DPA 签署完成 |
| 4. 交付实施 | 4–8 周 | FDE | 生产集成、UAT、灰度上线 | 客户 UAT 书面确认 + 评测门禁通过 |
| 5. 持续运营 | 按月 | FDE + CSM | 周报、月度复盘、Badcase 闭环 | SLA 达标、续约 |

## 1. Discovery

- 至少一次**到客户现场**：坐在客服、运营团队旁边观察真实工作流（例如客服如何处理“快递显示签收但未收到”）。
- 拉取历史数据样本（经客户授权、在客户或平台合规环境中查看），统计 Top 问题分布。
- 产出指标基线：例如人工客服首响时长、售后处理时长、上新时效。
- 识别风险：数据权限（是否需要聚石塔）、平台规则、客户内部系统（ERP / WMS）接口情况。

## 2. PoC

- 先与客户确认 **PoC 评测集**（通常 200–500 条真实问题或任务，脱敏后使用）和验收指标，例如：
  - 客服 Agent：自动解决率 ≥ 60%，违规承诺 0 条，转人工准确率 ≥ 90%
  - 商品运营 Agent：标题与属性一次通过率 ≥ 85%，类目违规 0 条
- PoC 默认 2–4 周、最多投入 2 名 FDE；超出需 CEO 冬翔和技术主管云欢批准。
- PoC 期间每周与客户开一次进度会，最后一次会议出评测报告，**用数据说话**。
- PoC 未达标：写清原因（数据不足 / 流程不适合 / 平台限制），给出继续或终止建议，不硬推。

## 3. 签约

- SOW 写清：交付的 Agent 与范围、验收评测集与指标、SLA、客户需配合事项（数据、账号、接口人）。
- **DPA 必签**：明确数据范围、处理目的、存储位置（聚石塔等）、保存期限、删除方式、是否允许用于模型训练（默认**不允许**）。
- 范围外需求一律走变更单，FDE 不当场承诺。

## 4. 交付实施

- 项目铁三角：FDE 负责人 + SA + CSM，FDE 组长每周检查项目健康度（红黄绿灯）。
- 典型工作：平台连接器配置、客户知识库导入（商品资料、售后政策）、工具开发（查单、物流、工单）、Guardrail 配置、HITL 审核流配置。
- 上线前：完整评测集通过门禁（见[CI/CD 与评测门禁](ci-cd-release.md)）+ 客户 UAT 书面确认 + 压测（大促前按 10 倍日常峰值）。
- 上线采用按流量灰度，客服 Agent 首周保留人工抽检（每日 ≥ 200 条）。

## 5. 持续运营

- FDE 每周输出客户周报：核心指标、Badcase Top 10 与修复情况。
- 每月与客户复盘一次；每季度做一次业务价值回顾（节省人力、GMV 影响），由 CSM 主导续约沟通。
- Badcase 闭环：发现 → 录入 NEval → 修复（Prompt / 知识库 / 工具）→ 回归评测 → 发布，原则上 **3 个工作日内**闭环。

## 驻场工作

- 以下情况通常需要驻场：Discovery、上线首周、大促保障、客户重大问题。
- 驻场审批、差旅、补贴和行为规范见[差旅与驻场标准](../04-expenses-benefits/travel-policy.md)；数据安全要求见[客户数据安全规范](../08-security/client-data-security.md)。
