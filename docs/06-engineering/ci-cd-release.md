# CI/CD 与发布流程

> 文档负责人：质量与效能部 孙蕾、帆舟 Owner 高远｜最近更新：2026-09-10

## CI 流水线（GitLab CI）

所有仓库使用质量与效能部维护的标准模板 `include: project: devops/ci-templates`，标准阶段：

1. `lint`：代码风格、提交信息检查
2. `test`：单元测试 + 覆盖率（增量覆盖率 ≥ 80%）
3. `scan`：SonarQube、SAST、依赖许可证扫描
4. `build`：构建 Docker 镜像，推送到 Harbor
5. `deploy-dev`：feature 分支自动部署到 dev 环境

任何阶段失败都会阻止合并。CI 平均耗时目标 < 10 分钟。

## 发布到生产

所有生产发布**必须通过帆舟（Sailboat）**，禁止手工 kubectl apply 或登录服务器修改。

### 发布窗口

| 时间 | 规则 |
|------|------|
| **周二、周四 14:00–17:00** | 常规发布窗口 |
| 周一、周三 14:00–17:00 | 低风险变更（配置、前端静态资源），组长审批即可 |
| **周五 18:00 至 周一 10:00** | **封网**，禁止常规发布 |
| 法定节假日前一天 18:00 至假期结束 | 封网 |
| 双十一（11 月 1–12 日）、618（6 月 1–19 日） | 大促封网，仅允许 P0/P1 故障修复 |

### 发布步骤

1. 在帆舟创建发布单，关联 Jira 需求与 MR，选择 main 分支的 Tag。
2. 填写变更说明、影响范围、**回滚方案**、验证方式。
3. 审批：组长审批 →（高风险变更）部门负责人 + SRE 值班审批。
4. **先发布 staging 验证**，测试工程师确认后再发生产。
5. 生产采用**分批灰度**：1 个 Pod（金丝雀）→ 10% → 50% → 100%，每批之间观察至少 10 分钟核心指标（错误率、RT、业务指标）。
6. 发布完成后在发布单中填写验证结果；发布后 30 分钟内发布人必须在线观察。

### 回滚

- 任何人发现发布导致异常，**先回滚再排查**。帆舟发布单页面“一键回滚”，2 分钟内完成。
- 回滚后在钉钉“发布通知群”说明情况。

### 紧急发布（Hotfix）

- 仅用于修复 P0/P1 故障或严重安全漏洞，可在封网期间进行。
- 审批：部门负责人 + SRE 组长雷鸣（或当周 Incident Commander）；事后 24 小时内补齐 MR 评审与测试记录。

## 移动端发版

- 导购 App 每两周一个版本，`release/x.y` 分支冻结后只接受缺陷修复，由罗伊和测试负责人袁圆共同决定是否放行。
- 应用商店审核期间准备好回退方案（服务端开关）。
