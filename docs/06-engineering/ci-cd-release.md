# CI/CD、评测门禁与发布流程

> 文档负责人：质量与效能组 孙蕾、Launchpad Owner 高远、数据与评测组 许蔓｜最近更新：2026-10-01

## CI 流水线（GitLab CI）

所有仓库使用质量与效能组维护的模板 `include: project: devops/ci-templates`，标准阶段：

1. `lint`：ruff / ESLint、提交信息检查、Prompt 文件头检查
2. `test`：单元测试 + 覆盖率（增量覆盖率 ≥ 80%）
3. `scan`：SonarQube、SAST、密钥扫描、依赖许可证扫描
4. **`eval`**：对改动涉及的 Agent 跑 NEval 回归评测（客户项目仓库必选）
5. `build`：构建镜像推送 Harbor，打包 Prompt / 知识库版本
6. `deploy-dev`：feature 分支自动部署到 dev 环境

任何阶段失败都会阻止合并。

## 评测门禁（Eval Gate）

| 指标 | 门禁规则 |
|------|----------|
| 评测集总通过率 | 不得低于该 Agent 当前线上基线（允许 −0.5% 波动，需在 MR 说明） |
| 安全与合规用例（违规承诺、隐私泄露、站外引流、Prompt 注入） | **必须 100% 通过**，任何一条失败直接阻断 |
| 工具调用正确率（查单、退款建议等） | ≥ 95% |
| P95 响应延迟（客服 Agent） | ≤ 3 秒 |
| 单会话平均成本 | 不得比基线上涨 20% 以上（超出需 FDE 组长批准） |

评测集由 FDE 与客户在 PoC 阶段共同确认，上线后每周补充 Badcase。评测集的维护见[FDE 客户交付流程](fde-delivery-process.md)。

## 发布到生产

所有生产发布（代码、Prompt、知识库、模型切换）**必须通过 Launchpad**，禁止在客户控制台直接修改线上 Prompt，禁止手工 kubectl。

### 发布窗口

| 时间 | 规则 |
|------|------|
| **周二、周四 14:00–17:00** | 常规发布窗口 |
| 周一、周三 14:00–17:00 | 低风险变更（知识库内容更新、文案），FDE 组长审批即可 |
| **周五 18:00 至 周一 10:00** | **封网**，禁止常规发布 |
| 法定节假日前一天 18:00 至假期结束 | 封网 |
| 客户大促封网：双十一（10 月 20 日–11 月 12 日）、618（5 月 25 日–6 月 19 日）、年货节 | 仅允许 P0/P1 修复和客户书面要求的紧急变更 |

> 客户自身有发布冻结期的（例如品牌大促日前 3 天），以客户要求为准，由 CSM 提前在 Launchpad 登记。

### 发布步骤

1. 在 Launchpad 创建发布单，关联 Jira、MR 和 **NEval 回归报告**。
2. 填写变更说明、影响的客户租户、**回滚方案**、验证方式。
3. 审批：FDE 组长 →（高风险：资金类工具、模型切换、跨客户平台变更）部门负责人 + SRE 值班。
4. **先发布客户 staging 租户**，重要变更需客户在 UAT 中确认（由 CSM 收集书面确认）。
5. 生产**按流量灰度**：5% 会话 → 20% → 50% → 100%，每批至少观察 30 分钟的转人工率、差评率、工具错误率。
6. 发布后 1 小时内发布人保持在线；在客户项目群同步上线结果。

### 回滚

- 发现异常**先回滚再排查**：Launchpad“一键回滚”可同时回滚代码、Prompt 和知识库版本，2 分钟内完成。
- 客服 Agent 还可以在客户控制台一键切换为“全部转人工”作为兜底。

### 紧急发布（Hotfix）

- 仅用于 P0/P1 故障、合规风险（如 Agent 做出违规承诺）或严重安全漏洞，可在封网期间进行。
- 审批：FDE 交付部总监韩东 + SRE 组长雷鸣（或当周 IC）；事后 24 小时内补齐评审与评测记录。

## NAP 平台发布

- 平台每两周发布一个版本，`release/x.y` 冻结后只接受缺陷修复；平台升级先在内部租户和 2 个试点客户灰度一周，再全量。
- 平台升级可能影响所有客户，必须对所有客户的核心评测集跑一次全量回归。
