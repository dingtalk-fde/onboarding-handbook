# On-call 值班与故障处理

> 文档负责人：SRE 组长 雷鸣 & FDE 交付部总监 韩东｜最近更新：2026-10-01

## 故障等级定义

| 等级 | 定义（满足任一） | 响应要求 | 通报 |
|------|------------------|----------|------|
| **P0** | 多个客户的 Agent 全面不可用（如模型网关故障、NAP 运行时宕机）；**任何客户数据或消费者信息泄露**；Agent 大面积做出违规承诺或错误资金操作（错误退款/改价） | **5 分钟内**响应，15 分钟内拉起作战室 | 技术主管云欢、CEO 冬翔、商业化 VP 邓伟、受影响客户的 CSM，每 30 分钟同步 |
| **P1** | 单个 KA 客户的 Agent 不可用或严重降级（转人工率暴涨、平台连接器中断）；大促期间任一客户核心 Agent 异常 | 10 分钟内响应 | FDE 交付部总监韩东、SRE 组长雷鸣、客户 CSM，每小时同步 |
| **P2** | 单个客户非核心功能异常，有绕过方案（如日报延迟、部分商品知识过期） | 30 分钟内响应 | FDE 组长 |
| **P3** | 轻微问题，不影响客户使用 | 工作时间内处理 | 无需通报 |

> 涉及客户数据泄露、消费者隐私泄露或安全入侵的事件，**无论规模一律按 P0** 处理，并立即通知信息安全负责人白冰（见[安全事件上报](../08-security/security-incident.md)）。

## 值班制度

- **FDE 一线值班（按行业 FDE 组）**：每组每周一人，周一 10:00 交接，负责本组所有客户 Agent 的告警和客户工单。
- **二线值班**：FDE 组长或高级 FDE，一线 15 分钟未响应或无法处理时升级。
- **平台值班（Agent 平台部）**：负责 NAP 运行时、连接器、模型网关。
- **SRE 值班**：7×24，负责基础设施、聚石塔/云鼎等环境和跨团队协调。
- **Incident Commander（IC）**：雷鸣、高远、马骁、韩东轮值，P0/P1 时统一指挥。
- 值班表在 Launchpad“值班中心”查看，换班需双方同意并在 Launchpad 修改。
- 新人入职约 60 天后先参加一周“影子值班”，转正前后正式进入轮值。

## 常见故障与第一反应

| 现象 | 第一反应 |
|------|----------|
| 某模型供应商超时 / 报错率升高 | 模型网关切换备用模型（Launchpad 预置开关），观察评测抽检结果 |
| 电商平台 API 限流或授权过期 | 联系客户重新授权（经 CSM），连接器降级为只读 |
| Agent 回答出现违规承诺或胡编 | 立即在客户控制台把相关意图切到“转人工”，回滚最近的 Prompt / 知识库发布 |
| 大促流量超出容量 | SRE 扩容；客服 Agent 开启排队与转人工分流 |

## 故障处理流程

1. **发现**：告警（夜莺电话/钉钉）、客户工单（客户成功部升级）、客户群反馈、员工上报。
2. **响应**：值班人在告警群回复“我已接手”，判定等级。
3. **升级**：P0/P1 在钉钉群“故障作战室”发起，@当周 IC。
4. **止血优先**：回滚、切模型、切人工、降级，**先恢复服务再查根因**。
5. **客户沟通**：由 CSM 统一对客户沟通，FDE 不在客户群里单独给结论；对外口径由 IC 和黄佳怡确认。
6. **恢复确认**：核心指标恢复正常 30 分钟后，IC 宣布故障结束。

## 复盘（Postmortem）

- P0、P1 故障必须在 **3 个工作日内**完成复盘（Confluence 模板“故障复盘”），在每周五 10:30 的“稳定性周会”讲解。
- 复盘原则：**对事不对人（Blameless）**。
- 涉及 Agent 行为的故障，必须把相关会话加入 NEval 评测集，防止复发。
- 改进项录入 Jira（标签 `postmortem`），由 SRE 组跟踪到关闭。
